# CBIR Image Similarity

**Язык:** Русский | [English](README_en.md)

Система визуального поиска похожих изображений на основе эмбеддингов.
Проект позволяет загрузить датасет, выбрать или загрузить модель-экстрактор, рассчитать эмбеддинги изображений, выполнить поиск похожих объектов и оценить качество выдачи с помощью retrieval-метрик. Дополнительно доступна загрузка уточняющей reranking-модели. Проект позволяет быстро проверить, насколько хорошо разные модели извлекают признаки изображений для задачи поиска похожих объектов.

## Структура репозитория

```text
cbir-image-similarity/
├── ResNet10TI/                     # материалы по собственной модели ResNet10TI
├── datasets/                       # примеры датасетов
├── experiments/                    # результаты экспериментов
├── extractors/                     # сохранённые extractor-модели
├── retrieval_reranking_CBIR.ipynb  # основной ноутбук с приложением
└── save_extractor_models.ipynb     # ноутбук для сохранения extractor-моделей
```

## 1. Клонирование репозитория

Чтобы воспользоваться решением, необходимо клонировать репозиторий на своё устройство:

```bash
git clone https://github.com/MachineTrof/cbir-image-similarity.git
```

## 2. Запуск приложения и ngrok

Проект рассчитан на запуск через основной ноутбук `retrieval_reranking_CBIR.ipynb`.

Для запуска через Google Colab был использован `ngrok`.

Порядок действий:

1. Зарегистрируйтесь на сайте `ngrok` (https://ngrok.com).
2. Создайте и скопируйте свой `ngrok authtoken`.
3. Откройте `retrieval_reranking_CBIR.ipynb`.
4. Последовательно запустите все ячейки основного ноутбука.
5. Когда ноутбук попросит `ngrok authtoken`, вставьте свой токен.
6. После запуска Streamlit-приложения откройте ссылку, которую выдаст `ngrok`.

Если `ngrok` использовать не хочется, можно заменить его на альтернативы: `localtunnel`, `Cloudflare Tunnel` и другие.

## 3. Формат датасета

Датасет должен быть загружен в формате `.zip`.

Для расчёта retrieval-метрик датасет должен иметь структуру `ImageFolder`, где каждая папка соответствует отдельному классу:

```text
dataset/
├── class_1/
│   ├── image_001.jpg
│   └── image_002.jpg
├── class_2/
│   ├── image_001.jpg
│   └── image_002.jpg
└── class_3/
    ├── image_001.jpg
    └── image_002.jpg
```

Изображения из одной папки считаются релевантными друг другу.
Если классы не найдены, поиск похожих изображений будет работать, но метрики по классам будут недоступны.

## 4. Использование собственной модели

Пользователь может загрузить собственную модель в формате `.pth` или `.pt`.

Ожидается, что модель сохранена как полный PyTorch-объект:

```python
torch.save(model, "my_extractor.pth")
```

Модель должна работать как extractor, то есть возвращать эмбеддинг изображения. Ожидаемый формат выхода: `[batch_size, embedding_dim]`.

Если используется собственная архитектура, её классы нужно добавить в код основного ноутбука между импортами и словарём `TEXTS`.

## 5. Добавление моделей Hugging Face

Встроенные модели задаются в словаре `RECOMMENDED_MODEL_CONFIGS`. Чтобы добавить новую модель с Hugging Face, нужно указать её тип и `model_id`.

Если нужно добавить новый тип моделей, которого нет в текущей реализации, можно написать дополнительный класс-обёртку по аналогии с существующими `Recommended_Extractor`.
